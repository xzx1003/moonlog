# 合成异常评测核心 v1

这不是生产事故 Ground Truth，也不是独立人工标注的真实故障集。标签来自公开的注入规则，独立于任何检测输出，适合可重复比较算法局限，不能证明实际服务故障准确率。日志解析不在此评测范围：适配器把桶直接交给生产 `detect_spikes`，不是 Python 仿制算法的成绩。

## 协议（看测试成绩前固定）

- 每桶5分钟，每条序列96桶。调参/测试各18条：6种场景各3个独立随机种子。正常、突发、持续、流量上升、周期任务、低流量；完整计数、标签和种子随结果保存。
- normal为1/2/3计数波动；burst注入4桶20..30错误；sustained注入30桶；low-volume在零背景注入4桶1..2错误。三者为正标签。
- traffic将12桶总量和错误数同步放大10倍，periodic每12桶一次20错误，定义为本评测任务中的正常行为，负标签。正负标签是任务假设，不是从日志数量就能客观判定的故障真相。
- index80标注未知，评分排除但仍更新基线；所有算法统一排除前12桶（搜索的最大预热窗口）。算法自己的预热仍按参数执行。
- 全序列划分，调参种子1000段、测试种子9000段；没有相邻桶随机拆分泄漏。不过两组来自同一套生成模板，不代表跨业务泛化；仅有3个重复，不给置信区间或显著性结论。
- 各算法24次搜索：window 3/6/12 × min_errors 1/3 × 4个算法参数。MA multiplier 2/3/4/6；EWMA alpha .1/.3/.5/.8、multiplier固定3；MAD k 2/3/4/6。等预算不代表穷尽或同等参数空间，EWMA未搜索multiplier。
- 仅用调参集微平均桶级F1选参，平分选更低误报率，再平分保留网格顺序。全部算法先锁定选择，再评分测试集；同时报告默认参数成绩。无阈值后调、未挑最好测试样本。

## 指标

桶级微平均 TP/FP/FN/TN；Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)，误报率=FP/(FP+TN)。分母0输出null；事件数与计数单独保留。

事件是原始标签连续True区间；未知标签断开事件。完全位于预热内的事件不评分；跨预热的左截断事件列出但排除事件召回与延迟。只要区间内至少一桶报警就算检出，因此事件召回高不等于完整识别持续事故。首次命中距事件起点 ×5分钟为延迟；未检出延迟null，另报missed_events。延迟摘要仅统计已检出且非左截断事件，不可遗漏同时报告未检出数量。

持续场景的逐桶 `reference_trace` 来自独立Python公式，包含判断前baseline、threshold与hit。每次都核对实际MoonBit命中桶、区间错误数和首桶baseline一致。轨迹可用于检查故障进入基线后停止报警，不能冒充生产内核内部浮点状态采样。

## 运行

```bash
moon build evaluation/adapter --target native --release
python3 -m unittest discover -s evaluation -p 'test_*.py'
python3 evaluation/run.py --output /tmp/moonlog-evaluation.json
```

仅需Python标准库与MoonBit。输出文件已存在会拒绝覆盖。保存全部搜索得分、选择参数、默认/选定参数逐序列预测、混淆矩阵、场景级/总体指标、持续异常轨迹、完整数据标签、数据/源码/二进制哈希和工具链信息。git提交号与dirty状态同时记录，未提交运行不能冒充干净提交结果。

结果入口：`results.synthetic-v1.json`。这是一套初步算法验收，不替代公开人工标注生产事故数据集。后续扩大数据集必须冻结v1记录，新协议另存版本，不改标签迎合结果。

连续真实事故的输入契约和固定默认参数验收命令见 [REAL-DATA.md](REAL-DATA.md)。入口已实现，但尚无独立标注的生产事故样本，因此没有真实故障准确率成绩。

基线污染策略对照与复现见 [POLLUTION.md](POLLUTION.md)，原始轨迹见 [results.pollution-v1.json](results.pollution-v1.json)。EWMA冻结更新只在评测中使用，生产默认未改变；持续异常检出与健康水平变化误报之间存在权衡。
